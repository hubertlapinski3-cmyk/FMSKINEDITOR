## The framework (`skin_editor/render/fixtures.py`, data in `tests/fixtures/render/<name>/`)
A fixture is DATA: `fixture.json` (what is rendered, where its truth comes from), optional `dump.json` (the live elements: boxes, resolved values, text, structural path), optional `project.json`, and `expect.json` (the checks). One generic test (`tests/test_fixtures.py`) runs every folder; kinds are `boxes`, `values` (exact), `rule`, `table`, `tiles`, `screen`. Rows are PASS, FAIL or N/A; nothing is filtered or re-toleranced (owner's tolerance: 8 px or 5 percent of the size, whichever is tighter; colours, font sizes and flex values exact). `python -m skin_editor fixture add --name N --capture C.ndjson --host H --layout L [--project P.json]` builds a fixture from a capture and fills its expectations; `fixture run --report DIR` runs all and publishes the report. Every FAIL row carries a named cause from a rule over the row, or says UNEXPLAINED (none are in the draft). The regression gate is `tests/fixtures/render/baseline-failures.json`: a failure not listed there fails the test; an improvement never does.
