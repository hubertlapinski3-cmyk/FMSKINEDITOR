## 1. height:100% (hypothesis H-pct): STAYS OPEN, with a new direct measurement

What the capture can and cannot show:
- `inline` holds only the `IStyle` entries set from code. Styles from a layout's own `style=` attributes (height 100%, flex-basis 0px, flex-grow...) are NOT in `inline` (the Medical Centre Frame, declared `flex 1 0 0px; height 100%`, has `inline = {}`). So declared height:100% cannot be read from the capture; it has to be paired with the layout render by name.
- `resolved.flexBasis` is the engine's resolved (layout-computed) basis, not the declaration: `NaN` = auto, otherwise a number. Over the 7,968 elements: grow>0 -> basis 0 on 1,010, auto on 131, a number on 266; grow=0 -> a number on 5,269, 0 on 997, auto on 295.
- Pairing every tile layout's declared "height 100%, basis auto, in a column parent, with siblings" cases to the screen (by type + unique name): the only candidate that pairs is the Loans `StreamedTable` (unnamed; unique by type). The Tactics overlay is absolute in a row (not a case). TrainingMentoringTile_4x4 and the TrainingOverview graphs are not on this screen (the Training host matched no mentoring layout). So no NEW discriminating element exists on this screen.

The Loans table, measured: parent `Frame_10000025` (Column, 106.4 high, grow 1, shrink 0, basis 0) holds a row `Frame_10000030` (24.4, grow 0, shrink 1, basis 24.41) and `StreamedTable` (82.0, grow 1, shrink 1, **resolved flexBasis 0**). The layout declares the table `flex-grow 1; height 100%` with no basis; no sheet rule sets a flex-basis on `.streamed-table` or `.streamed-list-view` (searched the index), and `inline` holds only `flexDirection: Column`. So the engine resolved the declared auto basis plus `height:100%` of a still-flexing parent to 0, and the grow filled the rest: 106.4 - 24.4 = 82.0. A CSS shrink model (basis = 100% = 106.4, shrinks to 19.8) does not reproduce it.

Verdict: the mechanism is now observed on the c2 element itself (second kind of evidence: the basis, not only the sizes), but it is still ONE element. The Medical Centre read stays non-discriminating (declared basis 0px). Per the two-source rule H-pct is NOT made a render rule. Needed: one more element with declared `height:100%` + auto basis + grow>0 in a flexed column with a sibling (candidates by layout scan: TrainingMentoringTile_4x4 `StreamedObjectList#GroupsList`, TrainingOverviewTile_4x2/4x4 `Graph_is-on-holiday`), on a screen that shows them.
