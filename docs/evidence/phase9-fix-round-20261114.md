## Problem 1: failure causes
Each failing row is examined individually (`skin_editor/render/causes.py`): pairing checks, the x/y/w/h split against each tolerance, inherited against origin by neighbour displacement (parent, parent centred, preceding sibling, space-between share, complement of siblings, sum or maximum of children, content of child, a partial share), a mechanism for each origin component with one independent capture fact, UNEXPLAINED otherwise, and two per-row overrides listed by id. 80 failing rows (78 shipped plus two new as-read variant rows): **38 origin, 42 displaced; 62 measured fact, 10 magnitude only, 8 UNEXPLAINED; the 1.0.0 label disagreed on D = 34 rows** (33 rows satisfied two of the old rules). Rule changes were stated before each blind re-run and are in the commits: `af2a89b` (rules frozen before the first all-rows run; first result: 34 unexplained, 16 of them a method artefact), `5a661f3` (inheritance candidates, loop origins chosen by mechanism fit, two rules added); after that the wrapper rule was tightened (width only, the game's own sheet must declare a row direction for a wrapper class, the render must have stretched the node to its parent's width) and the unexplained secondary components are recorded.
Findings against the brief: the nine title rows are not "bound text width" nor "Training schedule": the live scroller holds ScrollView wrapper elements the layout does not have (`unity-content-container--horizontal`), its content container is laid out as a row, the render stretches the title text to the full width (the 230 px), and SIVisible carries `display: None` set in code (inline in the capture). Thirteen Tactics rows are the title and header strip: the three header cells are narrow by the 15.6 px icon the render draws at 0 by 0 (the live icon gets 16 px width and height and flex-shrink 0 from a sprite class the game adds in code and the layout lacks: applying the live classes through the game's own sheet reproduces 16 px and the five flex-shrink rows), offset by text deltas; the cells' x positions are the space-between redistribution of those widths. The `#2E3138` Loans tile row is a hover capture (mask 2; the game's own `.layout-tile-interaction-button:hover` declares exactly that); the FAIL stays as scored and a paired PASS row was added. The UNEXPLAINED rows: the Training tile's 45.8 px, the Tactics title row and scroller, the Loans title row and scroller (text differs), the c2 dump's scroller (no capture facts), one out-of-possession icon x, and the Atmosphere status text colour. Rules naming a fixture or a literal colour were not used; the club-colour rows are graded magnitude only (the value is among the recorded run-time sheet's sampled values; this element's own rule is not in the 80-rule sample).
Honest limits: the examiner wrote the rules and no second person checked; 5 rows have a primary cause and a further origin component with no mechanism; 8 rows were flagged at the pairing step (an invisible live partner, or the render's sample text differs from the live text).
